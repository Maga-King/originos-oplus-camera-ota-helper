# 欧加相机 OriginOS OTA 助手（开发中）

目标：Windows 离线选择“目标 OriginOS 原包”和“本机欧加原厂 ROM”，从零生成模块。不要求已安装相机模块，不自动刷机，不依赖 WSL；GUI 与命令行使用同一个构建核心。

## 2026-09-27 原目录更新：自选 ZIP 输出与作者

- UI 新增“模块作者（author）”。留空或只填空格，module.prop 默认写“科比”；填写后使用自定义作者。
- 构建完成自动弹出 Windows“另存为”窗口，选择 ZIP 的保存位置和文件名。
- 原“输出目录”现在标为“构建缓存及报告目录”。编译中间文件、原成品、取材记录及教程仍放在那里；取消另存不会丢失成品，可点击“另存成品 ZIP…”重新保存。
- 另存采用后台复制，复制完成后才替换目标文件；失败时保留原成品。
- 命令行 JSON 项目可在顶层填写 author；直接运行 workflow_origin.py 可传 --author，不填同样默认“科比”。
- 按用户要求原地更新到 v0.1.1_非解包修复版目录，不另建目录；内部版本号为 0.1.2。此次只编译发布，测试由用户执行，下面的测试结果均是此前版本的历史记录。

## v0.1.1：非解包模式 Dolby 取材修复

旧版误把修复模块生成的 vendor/etc/media_codecs_dolby_vision_playback.xml 当作手机必备原件。原生系统只有 odm/etc/media_codecs_dolby_vision.xml 时，会错误停止。本版从本机 vendor/odm 标准杜比文件和 codec Include 链提取有效声明，生成缺失注册项；保留硬件自己的尺寸、码率等限制，不放开 XML 注释中的样例，不重复注册已有解码器。

可选目录不存在会跳过；root/SELinux 拒绝、设备断开会明确报错，不冒充“缺文件”。原厂 dolby_vision.cfg 按实际路径收集，不拿其他机型显示参数兜底。

已在当前一加13 OriginOS 上通过不填两份解包目录、只读 ADB 的完整构建测试。生成成功不代表新包已刷入验收；纯 ADB 模式依然不能读取未运行 ColorOS 的 system/product，美颜 JNI 和离线 CIL 合并限制会写入报告。

## 当前落地（2026-09-26 开发版）

- `media_patch.py`：基于目标系统原生 libstagefright.so，动态定位并修补杜比 RPU 封装和 vivo 杜比缩略图调用。不改 vivo 相册 APK。
- 不以序列号、ROM 指纹或整文件哈希限制构建；定位看函数、调用目标、参数准备和入口指令，无法确定时说明缺失规则，不拿旧版系统库冒充适配成功。
- 原生补丁只修改指定请求。缩略图要求 Vivo thumbnail=1、DV profile8/compat4、非加密解码、准确的 decoder 名称与 MIME。其他 DV profile、正常播放、编码保持原路径。

完整模块构建流程与中文 GUI 已接入，保存的原件测试集已经走完整个流程。仍是开发预览版：不能把静态构建成功当作其他机型全部功能已验证。测试集是本机归档原件与部分配置，不是第二台手机的完整ROM。

双击 `OriginOSCameraOTA.exe`，选择目标 OriginOS、本机欧加原厂解包和保存目录，点击“从零构建模块”。便携版自带 Python 运行时及最小 Windows LLVM 工具链，无需安装 Python/WSL/NDK。不会自动安装模块或重启。

## 开发运行

依赖相邻 `../OplusCameraOTA/native.py` 的 ELF 解析器（沿用现有工具），Python 的 pyelftools、capstone，Windows NDK clang/ld.lld。

```
python media_patch.py --input <目标libstagefright.so> --output <输出目录> --toolchain <Windows NDK bin目录>
```

便携版已打包工具链与依赖，编译器路径会自动填写。仅源码开发版需要自己提供工具链。本阶段不操作刷机或重启。

## 输入与可选 ADB 备用取材

始终保留目标 OriginOS 解包、本机欧加原厂解包两个目录选择器。ADB 备用通道由用户主动开启，多台在线设备必须明确选择；不开启时构建不执行任何 ADB 命令。

目录原件优先，缺失时按用户选择从当前设备只读缓存。目标系统核心库只有明确勾选“从当前运行系统补充目标文件”才读取，避免把主系统库混入 DSU 目标。原厂备用通道默认只允许 vendor/odm，不用运行中的 OriginOS system/product 冒充 ColorOS 原厂文件。

dumpsys 不是强制输入。必须确认的是 tag 编号/类型和镜头实际映射；离线声明若只包含运行时分配前的索引，不能把它伪装成最终编号，此时可补 dumpsys 或专用 HAL 导出。没有可用编号时只报告真正缺失的信息，不编造默认值。

`sources.py` 和 GUI 已接入本地优先、可选只读 ADB、设备选择、缓存和来源清单。缓存包含运行时诊断信息，不自动上传或塞入公开发布包。当前设备若启用了覆盖系统核心库的模块，ADB 可能读到修改件；优先选择原始解包，不能通过重复 patch 修改件适配OTA。
